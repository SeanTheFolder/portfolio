Claude Code &amp; MCP Workflow Integration for IT and Security

Integrated Claude Code into the daily IT and security workflow at Harbors. KQL detection rule authoring, runbook drafting, infrastructure-as-code review, and ad-hoc scripting handled through Claude Code with custom CLAUDE.md context and MCP servers wired to internal systems for grounded answers.

01 / The problem

A lot of the operational work in a small security team is high-skill writing and reasoning that does not scale linearly. KQL queries, Sentinel detection rules, runbook documentation, policy text, and PowerShell automation all consume hours per week. Most of that work is not novel each time. It is the same patterns applied to slightly different inputs. The right tool for that is an LLM with the right context, not more headcount.

02 / The approach

  1. Wrote a CLAUDE.md at the root of the operations repo that captures organizational context, naming conventions, the security tooling in use, and the 'house style' for KQL, PowerShell, and Markdown documentation
  2. Stood up MCP servers that give Claude Code grounded read access to internal documentation, the current Sentinel workspace schema, and the current incident queue. Read access only, with audit logging on every call
  3. Standardized on Claude Code for KQL authoring against Sentinel, with the model producing a draft and the analyst reviewing and tuning before deployment to production rules
  4. Used Claude Code for runbook drafting from incident write-ups. The analyst describes what happened and what they did, and Claude produces a structured runbook ready for the wiki
  5. Codified the rule that Claude is a force multiplier for the analyst, not a replacement for their judgment. Every output gets reviewed before it lands in production

04 / What I learned

The difference between a useful AI workflow and a frustrating one is context. A model with no context produces generic output you have to fix. A model with a well-written CLAUDE.md and grounded MCP access produces output you mostly accept with light edits. The investment in context is paid back within the first week of use. Also: keep the human reviewer explicit. The moment you start treating AI output as authoritative, you stop noticing the mistakes. Reviewer-in-loop is not about distrust, it is about quality.
