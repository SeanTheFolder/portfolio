Microsoft Sentinel: SIEM Build from Zero

Stood up the organization's first SIEM from absolute zero. Microsoft Sentinel with custom KQL detection rules, 12+ data connectors, and Logic Apps playbooks for automated response. Replaced isolated alerts with unified, correlated visibility.

Date
August 2024
Duration
8 weeks
Scope
Enterprise
Status
Completed

01 / The problem

There was no SIEM. No centralized log aggregation. No correlation between endpoint, identity, network, and cloud alerts. Security events lived in isolated tool consoles where nobody was watching.

02 / The approach

  1. Architected the Log Analytics workspace with retention tiers matched to HIPAA audit requirements and budget reality
  2. Onboarded 12+ data connectors covering Microsoft 365, Entra ID, Defender for Endpoint, Identity, O365, and Cloud Apps, plus WatchGuard firewalls and Azure activity logs
  3. Authored custom KQL detection rules for HIPAA-sensitive scenarios: unauthorized PHI access patterns, impossible travel, lateral movement indicators, and admin privilege escalations
  4. Built Logic Apps playbooks to auto-disable accounts on confirmed credential compromise and to enrich incidents with user and device context before analyst review
  5. Tuned alert thresholds against two weeks of baseline traffic to drive noise down before going live

04 / What I learned

KQL schemas vary significantly across connector types. What works for Defender for Endpoint logs needs different table references and parsing for Entra ID sign-in logs or Office 365 audit events. Building a small library of tested base queries before tuning alert thresholds saves weeks of noise reduction work later. Also: ingesting data is cheap. Ingesting the wrong data is expensive. Be deliberate about retention tiers from day one.
